# CONTEXTO COMPLETO — VOLLEYBALL SCOUT

## 1. OBIETTIVO DEL PROGETTO

Sto sviluppando da zero una web app chiamata **Volleyball Scout**, pensata per fare scouting di partite di pallavolo direttamente dallo smartphone durante una partita.

L'app dovrà essere:

* mobile-first;
* utilizzabile da smartphone durante una partita;
* successivamente utilizzabile anche da tablet;
* una PWA;
* utilizzabile offline;
* capace di salvare temporaneamente gli eventi sul dispositivo;
* sincronizzabile con il backend quando torna disponibile la connessione;
* ospitata inizialmente su un mio computer/server di casa;
* successivamente accessibile anche da remoto dalla palestra.

Il progetto deve essere sviluppato **passo passo**, perché sono un junior e voglio imparare cosa sto facendo.

NON voglio che vengano fatte modifiche enormi tutte insieme senza spiegazione.

# 3. FUNZIONAMENTO DELLO SCOUTING

Ci sono due modalità.

## BASIC

Pensata soprattutto per U15 e scouting rapido.

Per ogni azione:

* Punto
* Errore
* Ok

Quindi:

`POINT`
`ERROR`
`OK`

## ADVANCED

Pensata per scouting più dettagliato, ad esempio Serie C.

Si usano valutazioni:

`#`
`+`
`!`
`/`
`-`
`=`

IMPORTANTE:

I simboli rappresentano **l'efficacia dell'azione nel gioco**, non semplicemente la correttezza tecnica del gesto.

Non tutti i fondamentali devono necessariamente avere tutti e sei i simboli.

---

# 4. FONDAMENTALI

I fondamentali definiti sono:

```text
SERVE
RECEPTION
SET
ATTACK
BLOCK
DEFENSE
GENERAL
```

In italiano:

```text
SERVE      = Servizio
RECEPTION  = Ricezione
SET        = Alzata
ATTACK     = Attacco
BLOCK      = Muro
DEFENSE    = Difesa
GENERAL    = Generale
```

`GENERAL` è stato aggiunto appositamente.

Serve per registrare un punto/errore generale di un giocatore senza dover per forza classificare l'azione in un fondamentale.

Esempio:

un giocatore commette un errore durante un'azione di bagher ma non voglio necessariamente classificare quell'evento come "ricezione" o "difesa".

---

# 5. VALUTAZIONI ADVANCED

Valori disponibili:

```text
# = EXCELLENT
+ = POSITIVE
! = NEUTRAL
/ = SPECIAL
- = NEGATIVE
= = ERROR_QUALITY
```

Disponibilità attuale per fondamentale:

## SERVE

```text
# + ! / - =
```

Significati definiti:

```text
#  Ace

+  Buon servizio, l'avversario può fare solo un attacco prevedibile

!  Ricezione leggermente spostata, vengono forzate palle veloci/primo tempo

/  Servizio positivo, il ricevitore manda immediatamente la palla nel campo avversario

-  Ricezione positiva, l'avversario può utilizzare tutte le combinazioni di attacco

=  Errore al servizio
```

## RECEPTION

```text
# + ! / - =
```

Significati definiti:

```text
#  Ricezione perfetta al palleggiatore, tutte le combinazioni disponibili

+  Buona ricezione, tutte le combinazioni disponibili

!  Ricezione leggermente spostata, vengono forzate palle veloci

/  Ricezione negativa che termina nel campo avversario

-  Ricezione lontana dal palleggiatore, solo attacco prevedibile

=  Errore di ricezione, punto/ace avversario
```

## ATTACK

```text
# + ! / - =
```

Significati definiti:

```text
#  Punto

+  Costringe l'avversario a giocare una free-ball

!  Murato ma il pallone può essere rigiocato dalla propria squadra

/  Murato da muro vincente, punto al muro/avversario

-  Attacco debole, l'avversario può contrattaccare

=  Errore di attacco, punto avversario
```

## BLOCK

Per ora:

```text
# =
```

Significati definiti:

```text
#  Punto a muro

=  Errore di muro, fallo oppure mani-out
```

I significati di `+`, `!`, `/`, `-` NON sono ancora stati definiti.

NON inventarli.

## DEFENSE

Per ora:

```text
# + =
```

Significati definiti:

```text
#  Difesa tenuta/rigiocata che permette una rigiocata efficace

+  Difesa tenuta/rigiocata ma permette solamente una palla facile per il contrattacco

=  Errore difensivo, competenza non rispettata / posizione sbagliata
```

Gli altri significati non sono ancora definiti.

NON inventarli.

## SET

Per ora:

```text
# =
```

Significati definiti:

```text
#  Alzata perfetta

=  Errore di alzata
```

Gli altri significati non sono ancora definiti.

## GENERAL

Non ha valutazioni Advanced.

```text
GENERAL = set()
```

# 6. REGOLE DI PUNTEGGIO

La partita usa il sistema rally point.

IMPORTANTE:

Una `Touch` non significa necessariamente che il punteggio cambi.

In BASIC:

```text
POINT = il nostro team vince il rally
ERROR = il nostro team perde il rally
OK    = il rally continua
```

Il punteggio cambia solamente quando viene determinata la fine del rally.

La rotazione deve essere gestita in base alla conclusione del rally.

Regola generale:

* se riceviamo e vinciamo il rally → ruotiamo e serviamo;
* se serviamo e vinciamo → non ruotiamo;
* se perdiamo → non ruotiamo noi.

La logica completa di punteggio/rotazione verrà implementata più avanti.

NON bisogna ancora inventare come tutti i simboli Advanced chiudono un rally, perché alcuni significati non sono ancora definiti.

# 7. FORMAZIONE E ROTAZIONE

La squadra ha una formazione iniziale di 6 giocatori.

Le posizioni sono:

```text
P1
P2
P3
P4
P5
P6
```

La `Lineup` rappresenta la formazione iniziale.

Il `Set` invece conserva la situazione corrente in campo.

Questa distinzione è importante.

## Lineup

È la formazione iniziale del set.

Una volta creata, non viene usata per rappresentare le sostituzioni successive.

## Set current positions

Nel modello `Set` abbiamo:

```text
current_position_1
current_position_2
current_position_3
current_position_4
current_position_5
current_position_6
```

Questi rappresentano chi è **attualmente in campo**.

Quindi:

```text
Lineup = formazione iniziale
Set.current_position_* = situazione attuale
```

```python
    number = models.PositiveIntegerField()
    team = models.ForeignKey(
        Team,
        related_name='players',
        on_delete=models.CASCADE
    )

        return f"#{self.number} {self.name}"
```

# 13. MODEL MATCH

```python
class Match(models.Model):
    BASIC = "BASIC"
    ADVANCED = "ADVANCED"

    MODE_CHOICES = [
        (BASIC, "Basic"),
        (ADVANCED, "Advanced"),
    ]

    team = models.ForeignKey(
        Team,
        related_name='matches',
        on_delete=models.CASCADE
    )
    opponent = models.CharField(max_length=100)
    date = models.DateField()
    mode = models.CharField(
        max_length=20,
        choices=MODE_CHOICES
    )

    def __str__(self):
        return f"{self.team} vs {self.opponent} - {self.date}"
```

Una partita contiene:

* squadra;
* avversario;
* data;
* modalità BASIC/ADVANCED.

La data può essere anche passata perché vogliamo poter inserire partite già disputate.

```python
null=True
```

```python
def is_initialized(self):

        self.current_position_5_id,

```

Il set ha anche il vincolo:


```python
UniqueConstraint(
```

# 15. MODEL LINEUP

`Lineup` è collegato a `Set` con:

```python
OneToOneField
```

quindi esiste una sola formazione iniziale per ogni set.

Contiene:

```text
position_1
position_2
position_3
position_4
position_5
position_6
```

Ogni posizione è un Player.

Il metodo `clean()` controlla:

### 1. Nessun giocatore duplicato

I sei giocatori devono essere diversi.

### 2. Tutti appartengono alla squadra della partita

La squadra del giocatore deve essere:

```text
self.set.match.team
```

Se una formazione non rispetta questi criteri, viene generato un `ValidationError`.

IMPORTANTE:

Django non esegue automaticamente sempre `full_clean()` prima di `save()`.

Per questo nell'API facciamo esplicitamente:

```python
lineup.full_clean()
```

prima di salvare.

# 18. VALIDAZIONE TOUCH

La Touch viene validata in base alla modalità della partita.

## BASIC

Deve avere:

```text
outcome
```

Non può avere:

```text
quality
```

Errore:

```text
Una Touch BASIC deve avere un risultato.
```

oppure:

```text
Una Touch BASIC non può avere una valutazione avanzata.
```

## ADVANCED

Deve avere:

```text
quality
```

Non può avere:

```text
outcome
```

Inoltre la qualità deve essere tra quelle consentite per il fondamentale.

Esempio:

```text
BLOCK → # oppure =
```

Se viene inserito un simbolo non consentito:

```text
La valutazione '...' non è disponibile per il fondamentale selezionato.
```

Vengono inoltre controllati:

### Set corretto

Il set deve appartenere alla partita indicata.

### Player corretto

Il giocatore deve appartenere alla squadra della partita.

```python
current_players = [
```

Abbiamo capito che il backend deve essere la fonte di verità e deve impedire questo stato.

# 34. PRINCIPIO ARCHITETTURALE IMPORTANTE

Il backend deve essere la **fonte di verità**.

Il frontend non deve semplicemente "decidere" lo stato della partita.

Il frontend:

```text
mostra lo stato
↓
l'utente compie un'azione
↓
manda una richiesta API
↓
backend valida
↓
backend aggiorna il database
↓
backend restituisce il nuovo stato
↓
frontend aggiorna la schermata
```

Questo sarà particolarmente importante per:

* sostituzioni;
* rotazioni;
* punteggio;
* Undo;
* sincronizzazione offline.
